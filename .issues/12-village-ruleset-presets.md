## 背景・現状

- 村作成時、人数 / 役職構成 / 各種ルール（議論時間、配役比率、突然死設定等）を毎回個別に設定する必要がある
- 短期人狼には「12B」「11A」「13C」などコミュニティで定番化したルールセットが存在し、毎回同じ設定を再現するのは手間
- プレイヤー間で「12B でやろう」という会話が成立する文化があり、UI 上でも 1 クリックで再現できる方が UX が良い

## 対応方針

### UI
- 村作成画面の最上部（または分かりやすい位置）に **「プリセットから選ぶ」ボタン / セレクタ** を追加
- プリセット選択時、配下の入力項目（人数、役職人数、各種ルール）を一括で上書き
  - 上書き後もユーザーが個別カスタム編集できる（カスタムした瞬間「カスタム」表示に切替）
- 選択した時点でフォームの該当フィールドに値が反映される（送信前にプレビューできる）

### プリセットの定義
- **るる鯖（汝は人狼なりや？）の配役表を基準** に A / B / C / D 配役 × 人数（4〜30）を用意する
  - 出典: https://ruru-jinro.net/cast.jsp?p=kind
  - 詳細は本ファイル末尾「補足 1: るる鯖 配役一覧」参照
- **定番配役（コミュニティで頻出するもの）を別カテゴリで先頭に出す**
  - 例: `4A` / `6B` / `6C` / `8C` / `9D` / `10C猫` / `11C猫` / `11A` / `12A猫` / `12B` / `12C聴狂人` / `12D聴狂人` / `14D猫` / `16A` / `17A` / `18A猫` / `19D猫` / `30C強化猫`
  - 詳細は本ファイル末尾「補足 2: 定番配役村一覧」参照
  - UI 上は「定番配役」タブ / 「全配役（A/B/C/D × 人数）」タブの 2 階建てにすると探しやすい
- **アルティメット編成** など、配役 + ルールフラグ込みの独自プリセットも別枠で持つ
  - 詳細は本ファイル末尾「補足 3: アルティメット編成」参照
- 各プリセットは以下を持つ:
  - id（例: `a-12`, `b-12`, `c-13`, `d-9`）
  - 表示名（例: `12A`, `12B`）
  - 配役種別（A / B / C / D）
  - 人数
  - 役職構成（村 / 狼 / 占 / 霊 / 狂 / 狩 / 共 / 狐 / 信 / 背 / 猫 各人数）
  - 簡単な説明（任意）
- データの置き場所:
  - 案 A: **frontend 側にハードコード**（短期 / 定番セットなので動的更新不要 = シンプル）
  - 案 B: backend / DB 管理（運営が後から増やせるが overengineering）
  - **推奨: 案 A** から始める。必要になれば案 B へ移行
- UI 上の選択方式:
  - 配役種別（A/B/C/D）と人数を 2 段で選ばせる（例: 「B配役」→「12人」）
  - もしくは「12B」のように単一ラベルで列挙（数が多いので階層化推奨）

### プリセット ↔ カスタム の切り替え
- プリセット選択中に任意項目を変更したら自動的に「カスタム」表示に切り替え（プリセット強制リセット防止）
- 「プリセットに戻す」ボタンで再適用

## スコープ・注意

- スコープ外:
  - 運営 / 管理者が UI から新プリセットを追加・編集する機能（後続）
  - ユーザーが自分用プリセットを保存する機能（後続）
  - 既存村のルール変更時にプリセット適用（村作成時のみ）
- 注意:
  - **るる鯖の配役表をベースとする**（出典明記）。表の数値は機械的に転記し、ハイフン `-` は 0、`〜` の幅は **下限を採用するか可変扱いにするか要確認**
  - **「信（信仰心者）」「背（背徳者）」「猫（猫又）」** など本アプリで未実装の役職を含むプリセットの扱いは要確認（プリセットから除外 / 該当役職を 0 にして近似 / 実装側で対応 のいずれか）
  - 既存の村作成フォームのバリデーションと噛み合うこと（人数 = 役職合計、等）
  - 役職欄が動的に増減する UI なら、プリセット適用時に DOM 状態と state を整合させる必要がある

## 影響範囲

- frontend:
  - 村作成ページ（`frontend/app/pages/` 配下の village-create 系。着手時に特定）
  - プリセット定義データ（新規 `frontend/app/lib/village-presets.ts` 等）
  - プリセット選択 UI コンポーネント（セレクト or ボタングループ）
- backend:
  - 原則変更なし（プリセットはフロント側で展開してから既存 API に渡す前提）
  - もしバリデーション側で「プリセット名」を持たせたい要件があれば別途検討

## 動作確認

- frontend: lint / build
- 手動確認:
  - [ ] 村作成画面でプリセット（例: 12B）を選択すると、人数 / 役職欄 / 各種ルールが一括で適用される
  - [ ] プリセット適用後に役職人数を変更すると「カスタム」表示に切り替わる
  - [ ] 「プリセットに戻す」で再適用できる
  - [ ] プリセットを使わずに従来通り個別入力で村が建てられる（リグレッションなし）
  - [ ] 適用後にそのまま村作成を実行し、想定通りの構成で村が建つ
  - [ ] スマホ表示でプリセット選択 UI が崩れない
