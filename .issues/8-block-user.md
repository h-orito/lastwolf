## 背景・現状

- 現状、村建て主が特定ユーザーの入村を拒否する手段がない
- トラブルのあったユーザーや進行を妨げるユーザーを個別に避けたい需要がある
- ミュート的な機能は無いため、村建て主側で能動的に距離を取る選択肢を提供したい

## 対応方針

- ユーザー単位の「ブロックリスト」を新設（`blocker_user_id` → `blocked_user_id` の関係テーブル）
- ブロック動作:
  - **自分が建てた村に、ブロックしたユーザーは入村できない**（入村バリデーションで弾く）
  - **ブロックした相手が先に入村済みの場合は、村画面に「ブロックした人が入村しています」と表示**（参加者一覧やヘッダ近辺の注意領域）
  - 既に入村済みの相手を後から強制退村させる挙動は **スコープ外**（表示警告のみ）
- ブロック管理画面（追加 / 解除 / 一覧）をマイページ系に追加
- ブロック対象の指定方法は別途検討（プレイヤー名から検索 / プロフィール画面のブロックボタン 等。最小は検索 + ID 指定）

## スコープ・注意

- スコープ外: 既存入村者の強制退村、相互ブロック（ブロックされた側から村建て主の村が見えない、等）、メッセージ非表示などの「ミュート」系
- 自分が村建て主でない村（自分が参加してるだけの村）の入村制限はスコープ外
- 管理者（運営）アカウントへのブロックは無効にすべきか要確認
- 通報機能との関係: ブロックは私的な制限であり通報とは別物として扱う

## 影響範囲

- backend:
  - DB: ブロック関係テーブル新規（要 DBFlute のスキーマ追加 + マイグレーション）
  - 入村処理: 入村バリデーションに「村建て主が自分をブロックしていないか」のチェック追加
  - 村取得 API: 村建て主視点で「ブロック相手が参加者にいるか」フラグを返す
  - ブロック API: 追加 / 解除 / 一覧
- frontend:
  - マイページにブロック管理 UI を追加
  - 村画面で「ブロックした人が入村しています」警告表示
  - 入村時にブロックされている場合のエラー表示

## 動作確認

- backend: lint / build / 単体テスト（入村バリデーションのケース追加）
- frontend: lint / build
- 手動確認:
  - [ ] ユーザー A がユーザー B をブロックした状態で、A が村を建てて B が入村しようとして弾かれる
  - [ ] B が先に入村した村で、A が村建て主としてアクセスすると警告表示される
  - [ ] A がブロックを解除すると、B は新規に建てる村に入れるようになる
  - [ ] 自分自身はブロックリストに登録できない
- E2E: 既存 E2E にブロック関連シナリオを追加できるか確認

## release-note

- ブロック機能を追加。自分が建てた村に特定ユーザーが入村するのを防げます。既に入村済みの場合は警告表示されます。
